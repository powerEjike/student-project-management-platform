# ProjectTrack audit — 24 October 2026

This audit covers the current billing-disabled pilot. It provides evidence for the checks below, not a guarantee that every possible input, browser or future failure is bug-free.

## Corrections

- Firebase Auth initializes its emulator normally, and an emulator-only bootstrap connects Firestore before rendering the app. Previously Firestore connected only when the staff module loaded, leaving unauthenticated student registration outside the intended emulator setup. The conditional module avoids adding the Firestore SDK to production's initial sign-in download. Production configuration is unchanged.
- Opening a student approval review focuses its heading and brings the review into view, including on narrow phone screens.
- A failed department registration-session listener clears its ready/session state so the copy-link control does not keep using a previously successful check.
- Updated the development-only `ip-address` dependency from 10.7.3 to 10.7.4 through its existing compatible dependency range.

## Automated checks

- 247 application tests passed.
- All 66 Firestore integration permission tests passed, including department isolation, HOD roster intake, approval, allocations, project updates, chat, attendance and the connected project lifecycle.
- The encrypted backup and isolated restore rehearsal passed. It checks nested orphan history, timestamps, integer precision, bytes and reference rebinding using synthetic records.
- TypeScript and production build passed. The existing large-bundle warning remains; it is a performance consideration rather than a failed build.
- The deployed Firestore rules exactly matched the audited local source. All six required composite indexes were READY.
- All 258 files on the primary hosting site matched the local baseline build byte-for-byte. Release verification checks are repeated after publishing changes.
- Runtime dependency audit reported zero known advisories at the time checked.

## Browser checks

Used isolated `demo-projecttrack-audit` Auth/Firestore emulators and fake accounts. No real students, accounts, allocations, approvals, attendance or conversations were changed.

Inspected representative screens at desktop 1366×900 and phone widths 375 and 320 pixels:

- Super Admin overview, department settings and student approval review.
- HOD student allocation/workload navigation, department roster setup and received attendance report.
- Lecturer student cards, project topic/progress, document-review entry and floating chat.
- Student published overview/progress, check-in, attendance history, feedback/replies and department-specific signup.

Saved a synthetic staff chat message, completed a synthetic student class check-in, confirmed the attendance receipt in student history, sent a synthetic feedback reply, and submitted a Chemistry signup that remained pending administrator approval and email verification. Verified that approval review focuses the selected student's heading. Inspected mobile wrapping and page widths; wide tables remain within horizontal scroll containers. No broken image was observed in the inspected screens. The Firebase SDK logged one already-exists retry during concurrent department-channel creation; the chat loaded and the test message saved without a visible error.

## Remaining limitations

- Five development-tool audit entries remain: three high and two moderate, involving Firebase CLI and its `chokidar`, `braces`, `@google-cloud/pubsub` and `@opentelemetry/core` dependency paths. They are not shipped in the browser app. The suggested automatic remediation changes the Firebase CLI major version; no forced downgrade or incompatible transitive override was applied. These findings remain open and should be rechecked when the upstream toolchain is updated.
- Visual checks cover representative states, not every screen/input, browser engine, phone, assistive technology or long document. No new full production-data walkthrough was performed.
- The backup rehearsal does not establish that a private production backup schedule or operational recovery ownership is in place.
- Shared original-file storage, chat attachments and automatic email delivery remain outside the billing-disabled pilot. QR/account sharing still requires staff spot-checks.
- This release does not change Firestore or Storage permission rules. Existing department boundaries and Super Admin approval remain in force.
